# 中医药开源来源接入计划

六个候选仓库登记在 `src/integrations/tcm/catalog.ts`，核查依据见 [逐源研究](tcm-open-source-research.md)。登记代表研究入口，不代表医学审查、疗效认可或已经接入数据。当前所有候选的数据导入均关闭，没有运行上游程序、下载医学数据或添加运行依赖。

## 分层关系图

| 层       | 关系                          | 呈现要求                                                          |
| -------- | ----------------------------- | ----------------------------------------------------------------- |
| 传统理论 | 方剂—中药、君臣佐使、传统概念 | `traditional-theory`；逐条出处；不得等同现代机制                  |
| 现代研究 | 中药—成分—靶点—通路—疾病      | `modern-biomedical`；分别标记数据库关联、计算预测、实验或临床研究 |
| 评测研究 | MTCMB 等基准                  | 独立离线评测；不进入治疗建议或患者诊断流程                        |

图谱关联不能证明临床疗效。`clinical-effect` 只接受临床研究类型的记录；这只是结构检查，研究设计质量和结论仍需要具备资质的审查人员判断。每条边包含源记录 ID、源链接、证据 ID、审查状态；`reviewed` 必须记录审查人及日期。显示前还须解析证据 ID、核对原文、评估研究质量及确认实体身份，当前未实现发布流程。

## 导入前置条件

1. 固定上游提交和数据版本，核实项目身份及代码许可；分别核实上游数据库、教材、题库等原始材料的数据授权和再分发条件。
2. 留存数据权利审核记录后，才可将来源改为 `ADOPT`、`dataPermission: approved` 并登记具体数据许可。源码许可证本身不足以满足这些条件。
3. 编写离线导出适配器，通过 `validateLicensedGraph` 验证版本化 JSON 的源 ID、许可、唯一 ID、关系端点和证据分类。当前只有接口与校验器，没有真实源适配器。
4. 进行实体消歧、质量审查及医学审查；缺失引文、预测性结果或未审查记录不得作为临床结论发布。

不得引入剂量、患者记录、自动辨证、自动处方或上游 LLM Agent 执行链。大型导出、模型权重和第三方应用源代码不纳入本仓库。未来如需第三方代码复用，应重新评估项目待定许可证与上游义务的兼容性。

## 候选优先顺序

- 首先评估 tcm-cli 的数据组织方式和 TCMDATA 的 R 分析输出格式，分别核实其依赖数据库权限；Python/R 工具留在离线研究环境。
- Chinese_Medicine、Knowlegde_Graph_TCM、TCM_knowledge_graph 作为本体和关系建模参考，不复制其代码、数据或模型。
- MTCMB 独立评估数据集许可、逐源授权、隐私和训练/测试污染；评测得分不代表临床安全性或实际诊疗能力。

单元测试仅使用 `example.org` 和合成实体，验证拒绝未授权导入及错误证据分类，不产生医学事实。
