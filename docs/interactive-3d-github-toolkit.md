# Interactive medical 3D GitHub toolkit

Checked 2026-10-12. This is a focused engineering toolkit for a React/Vite medical education site, not a list of medical evidence or a claim that every candidate is installed. Existing dependencies stay pinned in `package.json` and `pnpm-lock.yaml`. The repository's current three procedural meshes remain visibly non-anatomical placeholders. No upstream application, source tree, model, dataset or binary was copied during this research.

Official GitHub repository metadata, latest-release endpoints, default-branch commits, README files and license files were checked. The immutable commit links below identify the research snapshot; releases and installed package versions are separate concepts. All listed repositories were unarchived when checked. A recent commit does not establish correctness, security or medical review.

## Repository optimization order

1. Complete the existing viewer's accessible selection, hiding/isolation, focus/reset and failure states using Three/Fiber/Drei and the current shared store. Keep non-WebGL controls usable and procedural placeholder labels explicit.
2. Add an approved asset manifest before anatomy import: source URL, immutable revision, original and transformed checksums, per-file license, attribution, dimensions/units, structure identifiers, reviewer and review date. Follow `anatomy-model-policy.md` and keep large binaries outside source control.
3. Validate approved GLB assets offline; measure geometry, texture memory, transfer size and device frame time. Introduce compression, LOD and BVH only where the measurements justify them.
4. Add imaging as a separately loaded module when a course need and data approvals exist. Maintain the course sequence from normal function through disease mechanisms, diagnosis, treatment and case reasoning; graphics libraries supply no clinical claims.
5. Extend browser coverage and audit accessible HTML equivalents. Research registration never counts as dependency installation, medical review or asset permission.

No runtime dependency change is recommended for the current procedural viewer. This focused toolkit supplements [the installed stack and existing candidates](open-source-stack.md), rather than duplicating full upstream applications into this repository.
